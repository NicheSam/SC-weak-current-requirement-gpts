# M1 固定版面資料契約

## 目的

`demand_map.html` 使用 `readable-v2` 固定版面。AI 負責判斷、拆分、轉譯、分類、摘要與語意覆核；`render_m1_outputs.py` 只把內容注入 `weak_current_html_template.html`，不得改寫工程語意。

禁止自行重建、簡化、替換 HTML、CSS、DOM 或 JavaScript。若 renderer 或模板執行失敗，應修正資料後重跑，不得改用手寫 HTML。

## 執行方式

1. AI 完成全案需求轉譯與覆核。
2. 將內容寫入 `m1_render_data.json`。
3. 執行：

```bash
python render_m1_outputs.py --data m1_render_data.json --output demand_map.html
python validate_m1_layout.py --html demand_map.html
```

4. 結構驗證通過後，AI 必須再閱讀實際 `demand_map.html`、`to_xmind.md` 與 `todo_handoff.md`，檢查需求完整度、轉譯品質、摘要與詳情分工、三檔一致性。AI 覆核未通過不得交付。

## m1_render_data.json

根物件：

- `project`：專案標題資訊。
- `requirements`：全部正式需求；不得抽樣、設上限或只放代表項目。
- `system_summaries`：每個實際系統一筆摘要，只描述系統角色與涵蓋範圍。
- `project_info`：專案資訊欄位。
- `smart_building`：智慧建築可能對應；只能寫可能對應。

每筆 `requirements` 必填：

| 欄位 | 用途 |
|---|---|
| `id` | 唯一穩定 ID |
| `navTitle` | 需求的短標題，供搜尋、定位與旁支輸出；HTML 樹狀葉節點仍顯示完整 `title` |
| `system` | 系統分類 |
| `group` | 子系統、空間或設備群 |
| `space` | 適用空間或對象 |
| `title` | AI 轉譯後的完整工程需求 |
| `source` | 來源頁碼或章節；可保留中間檔檔名供內部追溯，但畫面不得重複顯示 `source_document_clean.md` |
| `evidence` | 必要短原文依據 |
| `conditions` | 數量、性能、介面、供電、備援、測試或交付條件 |
| `status` | `clear`、`review` 或 `interface` |
| `review` | 待確認事項；無則寫「未見額外待確認事項」 |
| `docs` | 來源明示或合理需查核的圖說／文件，不可當正式交付判定 |

## 四頁籤分工

1. `需求樹核心`：左側以雙欄系統卡、縮排群組及完整需求葉節點為主要閱讀入口，右側顯示目前選取需求的快速詳情；兩欄之間提供可拖曳及鍵盤操作的寬度調整分隔線。
2. `詳細資訊`：逐筆完整需求、工程條件、適用資訊、來源、待確認及短原文。
3. `摘要總覽`：只有各系統摘要；不得放個別需求、來源頁碼、圖說清單、待確認清單或優先閱讀矩陣。
4. `專案資訊`：專案基本資訊與智慧建築可能對應。

特殊空間需求必須保留；它可作為實際需求系統或群組出現在需求樹與詳情中，不得只留索引，也不得建立內容重複的第二套需求。

`source_document_clean.md` 是 Docling 階段的傳遞檔名，不是給人閱讀的證據名稱。資料可保留原值，但 HTML 顯示時必須隱藏該檔名，將 `source_pdf_page N` 顯示為 `PDF p.N`，並保留原書頁碼。只有檔名而沒有頁碼或章節時，詳情顯示「來源頁未標示」，需求樹不產生無資訊量的來源標籤。

## 不可接受

- 把原文直接包進 HTML，未經 AI 轉譯。
- 需求樹葉節點顯示完整轉譯需求，但不得把工程條件、待確認說明與短原文全文全部重複塞入樹內；這些內容保留在右側詳情。
- 摘要混入詳情欄位。
- renderer 自行補句、分類、合併或刪除需求。
- validator 因語意或固定筆數阻斷成果。
- renderer 失敗時改交簡化 HTML。
- 自動開啟或內嵌 `demand_map.html` 預覽。
