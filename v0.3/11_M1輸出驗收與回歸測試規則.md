# M1 輸出驗收與回歸測試規則

測試分成來源抽取、AI 轉譯與閱讀成果三層。格式通過不能代替內容品質。

## 一、來源抽取

- PDF 所有可讀來源片段都進入來源閱讀批次，不因章節、關鍵字、語意分數或預設系統路由提前排除；空白頁與無法讀取頁另列狀態。
- 每個批次都有唯一 `screened`、`reviewed-pages`、`reviewed-groups` marker，且與 manifest 一致。
- `stage1_receipt.json` 的來源檔名、來源 SHA、PDF 頁數、篩選批次 ID 及 `weak_current_source.md` 雜湊必須與實際檔案一致。
- `weak_current_source.md` 只保留弱電相關原文、頁碼、候選 ID、章節與必要上下文，不是全文複製。
- 通過信心門檻或經模型視覺校正的 OCR，與原生文字同等採用。
- 低信心 OCR 必須留下草稿並交模型覆核；合併前不得殘留未判讀的 pending 影像區。模型已判為不可讀或非文字者不阻斷全案，疑似弱電且無法可靠辨識者要形成具體來源待確認。
- 未知設備或不同案型不能因未命中既有詞表而無聲消失。
- 全批次完成後依 manifest 群組輪廓做一次文件級漏項複核，只重讀疑似漏項批次。
- 第一階段不得摘要或合併不同義務；設備規格表、清單及段落內的獨立設備、規格、數量、供電／備援、材料、協定、操作、介面、空間及測試要求要逐項保留。

## 二、弱電業務召回

電信、資訊、電視、影音、通訊、監視、門禁、停車、廣播、對講、求救、感測、辨識、告警、BMS／BA、EMS、IoT、資安、資料平台、弱電基礎設施及跨系統訊號／資料／控制介面，都必須依語意檢查。

過往專案的已知證據點只用來離線驗證混合頁與業務範圍召回，不是當前案件來源，也不得出現在 GPTS 的本案轉譯判斷中。驗收本案時，只能核對本次 weak_current_source.md 實際保留的內容；來源包沒有的詞不得因回歸案例而補入成果。

## 三、AI 轉譯品質

每筆正式需求至少檢查：

- 動作、設備、訊號、線纜或介面是否明確。
- 空間或對象是否清楚。
- 義務強度、條件、數量、否定與例外是否保留。
- 跨頁補充是否合併，矛盾內容是否轉成具體人工確認。
- 是否自然、完整、可獨立設計或查核。
- 渲染前是否完成 AI 語意覆蓋複核，且來源包中的每個獨立義務都成為正式需求或明確子要求。

不得以原文殘句、程式拼句、共用責任說明、索引或 `依來源規格納入……` 代替 AI 轉譯。

## 四、舊版品質下限

以 `_archive/2026-07-17_readability_regression/demand_map_5.html` 及使用者確認滿意的舊版成果為基準：

- 新版不得漏掉舊版已呈現且來源成立的弱電需求。
- 系統與主題名稱必須能預告內容，不得大量一筆需求一個主題。
- 需求樹必須直接顯示完整需求，不得只顯示索引。
- 詳細資訊必須能快速辨識需求、空間、來源與待確認事項。
- 配色、縮排與留白至少維持舊版的可掃讀程度。

## 五、三份成果一致性

- `requirements_master.md` 是唯一語意主檔。
- HTML 正式需求數等於主檔 REQ 數。
- `to_xmind.md` 的系統、主題及需求文字逐字來自主檔需求樹。
- `todo_handoff.md` 的需求與人工確認來自主檔。
- ZIP 只包含 demand_map.html、to_xmind.md、todo_handoff.md。
- renderer 不得改寫需求文字。

## 六、HTML

- 需求樹採固定清單，不使用拖曳或縮放畫布。
- 專案、系統、主題、完整需求與證據摘要有清楚縮排及角色色彩。
- 系統、空間、狀態與搜尋篩選可用，選項由實際需求生成。
- 詳情預設不占樹寬，點選需求後展開並可關閉。
- 不得有模板占位符、重複 ID、文字直排、裁切或水平溢出。
- 桌面與窄螢幕皆可閱讀，不依賴外部網路資源。

## 七、真實回歸

至少使用一份實際混合型統需書：

1. 建立全部來源閱讀批次。
2. 由 AI 逐批抽取並產生 `weak_current_source.md`。
3. 驗證 `stage1_receipt.json` 的頁數、批次覆蓋與來源包雜湊成立，再驗證已知證據點進入弱電來源包。
4. 由 AI 依舊版方式建立 `requirements_master.md`。
5. 比較舊版需求覆蓋、自然轉譯、主題組織與閱讀體驗。
6. 渲染三份成果並檢查 HTML 操作。

大型 PDF 接近一小時不自動視為失敗，但必須真的執行並形成檔案；不得只回傳摘要、等待時間或假背景狀態。
