# HTML 輸出與閱讀規則

## 核心定位

HTML 是給弱電設計、工程協調與審查人員閱讀的需求圖譜，不是工程資料庫。

第一閱讀入口固定為需求樹。使用者不應先看統計欄位或大型關聯圖。

## 主畫面

採固定需求樹加按需展開詳情：

- 主區：沿用舊版層級明確的系統 → 主題 → 完整需求清單；寬螢幕的系統卡片採雙欄排列。
- 右側：只有點選需求後才展開，顯示完整文字、主題設計重點、系統摘要、可能圖說／文件、主要介面、空間、狀態、頁碼及短原文，並提供關閉按鈕。

層級色彩固定代表角色，不作裝飾：專案／需求樹使用深藍，系統使用藍色，主題使用綠色，完整需求使用橘色，ID／空間等證據摘要使用紫灰色。狀態色只用於狀態標籤。

禁止：

- 拖曳、放大、縮小或自由畫布。
- 只顯示小節點而看不到需求文字。
- 把詳細資料擠成過窄直排欄位。
- 以索引連結取代需求內容。
- 每筆需求顯示無資訊量的固定責任句。
- 讓每筆需求各自形成一個私人主題。

## 篩選

篩選選項由 `requirements_master.md` 的實際內容生成：

- 全文搜尋。
- 系統。
- 空間。
- 狀態。

不得在模板內預設固定系統或空間清單。清除篩選後恢復全部需求。

## 需求列

左側每筆需求至少顯示：

- 完整需求文字。
- 需求 ID。
- 空間。
- 狀態。

右側詳情顯示：

- 完整需求文字。
- 系統與主題。
- 適用空間。
- 來源明示／跨章整合／需人工確認。
- PDF 頁碼及候選 ID。
- 足以查證的來源短原文。
- 主題設計重點與系統設計意圖。
- 可能需要的圖說／文件及來源可支持的主要介面。

系統預設收合，只展開第一個系統；使用搜尋或篩選時，自動展開有命中需求的系統。系統摘要及主題說明必須讓使用者不點詳情也能理解該區塊用途。

## 輔助頁

摘要總覽只整理已完成轉譯的全案重點，不重新摘要 PDF。

人工確認頁只列具體問題、影響、建議確認對象、來源及短原文。

背景與排除頁只列容易與弱電混淆或會影響後續理解的項目，不逐頁堆積純建築內容。

## 技術品質

- 所有 HTML ID 必須唯一。
- 不得留下 `{{...}}`、TODO 或空白卡片。
- 桌面版點選需求後形成需求樹＋詳情雙欄；未選取時需求樹使用完整寬度。窄螢幕改為上下排列。
- 文字可正常換行，不得直排、裁切或水平溢出。
- 按鈕、篩選與折疊可使用鍵盤操作，焦點清楚。
- 不使用外部 CDN 或需要網路的字型、圖示與程式庫。
- 不在 ChatGPT 網頁中自動開啟 HTML 預覽。
