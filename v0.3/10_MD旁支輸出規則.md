# Markdown 旁支輸出規則

兩份 Markdown 都由 `requirements_master.md` 確定性投影，不重新摘要或改寫需求。

## to_xmind.md

用途：讓 XMind、其他心智圖工具或人工直接讀取唯一需求樹。

只包含：

```text
# 專案名稱
## 需求樹
### 系統
#### 主題
- 完整需求文字
```

規則：

- 系統、主題及需求文字逐字來自 `requirements_master.md`。
- 不輸出頁碼、候選 ID、短原文、統計、摘要或人工確認。
- 不建立第二套特殊空間索引樹。
- 需求筆數不得設固定上限。

## todo_handoff.md

用途：供後續 AI 或人工接續查核、設計協調與責任確認。

至少包含：

- 專案名稱及來源文件。
- 正式需求、系統及人工確認數量。
- 專案摘要。
- 各系統完整需求及來源頁碼。
- 各系統摘要、設計重點、主要介面與可能圖說／文件。
- 各主題說明及主題設計重點。
- 每筆人工確認的問題、影響、確認對象、來源及短原文。
- 背景與排除紀錄。

規則：

- 不得加入 `requirements_master.md` 沒有的正式需求。
- 正式需求文字不得為了交接重新縮寫。
- 人工確認不能只放 ID 或「來源不足」。
- 不輸出內部 OCR manifest、候選 JSON、暫存路徑或程式狀態。
- 本檔不是 M1.5、正式 RFI、估價表或 CAD 任務清單。

## 一致性

- `to_xmind.md` 的需求數等於主檔正式需求數。
- `todo_handoff.md` 的正式需求及人工確認數等於主檔。
- 三份交付中的需求文字不得互相矛盾。
